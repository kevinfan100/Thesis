\section{Hexapole Electromagnetic Actuating System}

This dissertation considers a Hall-sensor-based hexapole electromagnetic actuator for precision manipulation in aqueous solution. The system uses six independently driven poles connected through a common magnetic yoke. Because force objectives are three-dimensional while actuation is six-dimensional, the platform is over-actuated and requires explicit allocation and control design \cite{zhang2011design,long2021optimal,long2022hallsensor}.

From a control perspective, the platform is treated as a six-input six-output magnetic-flux generation system with coupling among channels. Hall-sensor measurements are embedded in the actuation loop, so downstream control decisions are based on measured magnetic variables rather than current command alone. This architecture provides the physical basis for the thesis chain from system identification to flux control and force generation.

At this stage, the chapter focuses on architecture-level description and shared physical definitions. Detailed model fitting, controller synthesis, and force-quality interpretation are developed in later chapters.

\section{Hexapole Force Modeling}

This section provides the minimum set of force-model interfaces required by the dissertation. The purpose is to define common mathematical objects and signal mappings used across chapters, without expanding full derivations.

\subsection{Magnetic-Flux-Based Hexapole Force Model}

The force-generation description follows the flux-based formulation and is written as
\begin{equation}
f_{m}(p,\phi) = g_{\phi}(\epsilon)\,\bar{f}_{m}(\hat{p},\phi),
\end{equation}
where $p$ denotes probe position, $\hat{p}$ denotes normalized position in the workspace, and $\phi$ denotes the six-channel magnetic-flux vector. This compact form is used as the control-oriented force-model interface in later chapters.

In this dissertation, the model is used to support design and interpretation tasks: mapping desired force behavior to actuator variables, relating channel coupling to force-output behavior, and defining consistent simulation-to-experiment comparisons.

\subsection{Hall-Sensor-Based Force Model}

Because flux is measured through Hall channels in practical operation, the model interface includes Hall-voltage mapping:
\begin{equation}
\phi = D_{H}v_{H},
\end{equation}
where $v_{H}$ denotes Hall-sensor voltage vectors and $D_{H}$ is the calibrated voltage-to-flux gain matrix.

This mapping is the key link between mechatronic measurement and force modeling. In later chapters, this interface is used to evaluate model consistency under the tested operating setup and to connect measured feedback variables to force-level interpretation.
The force-allocation procedure and its quantitative validation are reserved for Chapter 5.

\section{Mechatronic and Optical Integration}

This section describes how hardware, sensing, and operation software are integrated to support repeatable control-development experiments on the same platform.

\subsection{Real-Time Control Hardware Integration}

The implementation combines DAC-based command output, linear power amplifiers, coil actuation, ADC-based Hall-sensor acquisition, FPGA real-time execution, and host-PC supervision. In runtime operation, command and measurement channels are processed under one coordinated real-time framework for experiment execution and logging.

The FPGA side provides deterministic timing and channel management, while the PC side handles experiment setup, parameter management, and post-run data organization. This partition is used throughout the dissertation as the baseline implementation setting.

\subsection{Optical and Visual Tracking Integration}

The optical chain includes microscope imaging, camera acquisition, and objective-positioning hardware. Visual tracking is treated as an operation and validation interface that complements Hall-sensor-based magnetic feedback during experiment setup, monitoring, and cross-checking.

This section keeps a system-integration focus. Tracking algorithm details are not expanded here and are referenced only to the extent required for understanding the integrated platform workflow.

\subsection{Software Interface and Operation Flow}

To improve practical usability, the platform includes a PC-side software interface coordinated with FPGA execution. The interface supports experiment configuration, runtime monitoring, data capture, and workflow triggering for calibration and control-development tasks.

The planned operation flow in this dissertation is organized as: platform setup, experiment execution, synchronized data logging, and stage-wise handoff to the technical analysis chapters. The implementation details of identification automation and controller design are presented in later chapters.

\section{Summary}

This chapter defines the shared system foundation of the dissertation: platform architecture, force-model interfaces, and mechatronic-optical operation context. Based on this foundation, Chapter 3 develops system identification, Chapter 4 develops flux-control design and validation, and Chapter 5 develops force generation with cross-layer interpretation.
